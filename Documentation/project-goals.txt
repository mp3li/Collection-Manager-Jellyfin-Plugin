MEDIA COLLECTION MANAGER — CURRENT RELEASE GOALS
=================================================

Purpose
-------
Media Collection Manager is a Jellyfin 10.11.11 dashboard plugin for making
ordinary native Jellyfin collections from metadata that already exists in the
administrator's selected libraries. It reads Jellyfin-assigned metadata and
local-NFO metadata without fetching, adding, editing, removing, or replacing
any media metadata or NFO files.

The plugin is designed to work on its own and alongside the Media Tagging
Manager Jellyfin Plugin. Media Tagging Manager may assign useful existing tags
such as Provider and Network; this plugin treats those values as ordinary
metadata alongside every other metadata value already present in the library.
Provider and Network remain separate metadata types.

Current release scope
---------------------
The complete current release is limited to these four dashboard tabs. Further
dashboard areas will be designed in a later planning round.

1. Main Settings
   - Provide a clear explanation of existing metadata tags and the plugin's
     read-only metadata boundary.
   - Let an administrator select, save, select all, and select none for the
     Jellyfin libraries used by the plugin.
   - Store the newly-added-media preference for applicable automatically
     managed collection behavior.
   - Scan saved libraries into a local, read-only catalog of every available
     metadata value, including Jellyfin metadata, local NFO metadata, custom
     tags, and values assigned by companion tools.
   - Show scan progress and status.
   - Provide an initially collapsed My Metadata Tags Overview. Opening it
     loads every saved library expanded, with each library independently
     collapsible, ten titles per page, Title first, and one column for every
     discovered metadata type.
   - Provide the overview color control used by the dashboard style.

2. Individual Tag Collections
   - Show every saved library as an initially collapsed selector section.
   - Load metadata types only when a library is expanded, and metadata values
     only when a type is expanded.
   - Support all catalog metadata types, including Genres, Providers,
     Networks, Studios, Production Companies, Production Countries, Cast,
     Crew, Languages, Ratings and Classifications, Keywords, Existing
     Collection Metadata, direct Jellyfin fields, local NFO fields, and every
     other discovered type.
   - Sort values alphabetically; search values; page values fifty at a time;
     show matching counts; and show a person image when Jellyfin has one.
   - Create one live collection draft for every selected metadata value and
     remove that draft immediately when the value is unselected.
   - Let each draft have an editable collection title, an included/not-included
     creation choice, a current matching-media explanation, and a collapsible
     preview grouped by library.
   - Let each draft include matching media from additional saved libraries.
     The library where the value was selected is always included; Select All
     and Select None apply only to the other saved libraries.
   - Create checked, complete drafts as native Jellyfin collections, show
     progress and outcomes, and require a visible administrator choice before
     a same-title collection is used unchanged or skipped.

3. Combined Tag Collections
   - Reuse the full lazy, searchable, paginated metadata picker used by
     Individual Tag Collections.
   - Maintain one draft containing two or more selected metadata tags.
   - Display each selected tag's source library, metadata type, value, source
     matching count, and a per-tag removal control.
   - Match the union of the selected tags: an item matching any selected tag is
     included once, even when it matches more than one selected value.
   - Maintain one shared additional-library scope. Libraries where tags were
     selected are always included; Select All and Select None apply only to
     other saved libraries.
   - Provide an editable title, a collapsed preview grouped by library, a
     clear-draft control, visible same-title conflict choices, creation status,
     unique matching-media count, and a completion outcome.
   - Clear a successfully created draft so the administrator can start the
     next combined collection.

4. Multi-Match Tag Collections
   - Reuse the same full lazy, searchable, paginated metadata picker and
     shared-library scope as Combined Tag Collections.
   - Maintain one draft containing two or more selected metadata tags.
   - Match the intersection of the selected tags: an item is included only when
     it matches every selected metadata value in the shared selected-library
     scope.
   - Display each selected tag's source library, type, value, source matching
     count, and a per-tag removal control.
   - Provide an editable title, a collapsed preview grouped by library, a
     clear-draft control, visible same-title conflict choices, creation status,
     matching-media count, and a completion outcome.
   - Clearly state when no media matches every selected tag and prevent
     collection creation in that state.
   - Clear a successfully created draft so the administrator can start the
     next multi-match collection.

Native Jellyfin and safety requirements
---------------------------------------
- Collections created by this plugin are normal Jellyfin collections. Native
  Jellyfin collection actions, including artwork and image controls, remain
  available in Jellyfin.
- The catalog and previews use only the most recent completed metadata scan.
- Matching remains server-side and bounded: overview pages contain ten media
  items and metadata-value pages contain fifty values.
- No same-title collection is silently duplicated or changed. The visible
  choices are to use the existing collection unchanged or skip the draft; an
  administrator can also change the draft title.
- The plugin must not expose media paths, credentials, API keys, NFO contents,
  local logs, or other private runtime data in public project files.

Compatibility and packaging requirements
----------------------------------------
- Build against Jellyfin.Controller and Jellyfin.Model 10.11.11 using net9.0.
- Target the Jellyfin 10.11 ABI declared by the package metadata.
- Preserve the Media Collection Manager Noncommercial License 1.0.
- A repository manifest is created only for a real release ZIP. Its version,
  target ABI, framework, release source URL, SHA-256 checksum, timestamp,
  description, branding image, and changelog must describe that exact artifact.
