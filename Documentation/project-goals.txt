COLLECTION MANAGER — CURRENT RELEASE GOALS
=================================================

Purpose
-------
Collection Manager is a Jellyfin 10.11.11 dashboard plugin for making
ordinary native Jellyfin collections from metadata that already exists in the
administrator's selected libraries. It reads Jellyfin-assigned metadata and
local-NFO metadata without fetching, adding, editing, removing, or replacing
any media metadata or NFO files.

The plugin is designed to work on its own and alongside the Media Tagging
Manager Jellyfin Plugin. Media Tagging Manager may assign useful existing tags
such as Provider and Network; this plugin treats those values as ordinary
metadata alongside every other metadata value already present in the library.
Provider and Network remain separate metadata types.

Documentation maintenance
-------------------------
Every confirmed administrator-facing feature, behavior correction, and visual
requirement belongs in this file as part of the current product plan. Its
corresponding private verification belongs in goal-testing.txt. The changelog
records the implemented change, and README.md is updated whenever the public
description, tab list, installation guidance, or user-facing behavior changes.
An item is not described as runtime-complete until the private testing tracker
records a real Jellyfin result.

Dashboard visual system
-----------------------
- Match Media Tagging Manager's established shared dashboard hierarchy,
  alignment, spacing, control styling, and tab shape wherever equivalent UI
  exists. Do not introduce custom indentation, heading hierarchy, colors, or
  tab treatments that do not exist in that companion plugin.
- Use Jellyfin's native themed dialog support for dialogs so the active server
  theme supplies readable background, text, and control colors.

Current release scope
---------------------
The complete current release currently exposes eleven dashboard tabs. The five
art tabs below are intentionally blank placeholders until their separate
feature plans are defined.

1. Main Settings
   - Provide a clear explanation of existing metadata tags and the plugin's
     read-only metadata boundary.
   - Let an administrator select, save, select all, and select none for the
     Jellyfin libraries used by the plugin.
   - Store the newly-added-media preference for applicable automatically
     managed collection behavior.
   - Scan saved libraries into a local, read-only catalog of every available
     metadata value, including Jellyfin metadata, local NFO metadata, custom
     tags, and values assigned by companion tools.
   - Show scan progress and status.
   - Provide an initially collapsed My Metadata Tags Overview. Opening it
     shows the last available completed scan with its date and time, including
     after a Jellyfin restart. The scan's libraries load expanded and remain
     independently collapsible. Each metadata type is its own expandable tag
     picker containing actual metadata values—never media-title rows—with
     search, alphabetical values, matching-media counts, and fifty-tag pages.

2. Create Manual Collections
   - Show every Jellyfin library as an initially collapsed selectable-media
     section. Opening a library uses Jellyfin's supported typed item query for
     that library's configured content type, so the picker matches normal
     Jellyfin browsing: TV libraries show Series; movie libraries show Movies;
     book libraries show Books and Audiobooks; music libraries show Audio and
     Audio Album items; and video libraries show their applicable Movie or Video
     items. Folders, seasons, episodes, deleted scenes, and other extras are
     never collection choices.
   - Reuse the Collection Overview & Editor poster, title, type, year, and
     overview presentation for library media, adding a picker checkbox for each
     item and no collection-edit control. Decode any markup stored in a media
     overview into readable plain text before rendering it.
   - Give each expanded library picker a media search field and ten-item pages.
     Keep Select All and Select None between the previous and next page controls
     and show a small Page _ out of _ indicator. Use the same standard gray
     Previous Page and Next Page controls as the rest of the dashboard. The
     selection controls apply only to the ten visible choices on the current
     page. Keep the controls below the displayed media. Previous Page, Next
     Page, Select All, and Select None must preserve the administrator's actual
     Jellyfin dashboard scroll position.
   - Maintain one manual collection draft across any combination of Jellyfin
    libraries. Let the administrator enter a title and review every selected
     media item before creation. Label this section Individual Collection Draft
     because there is only one draft at a time.
   - Put a small inline Remove control beside every draft title. Removing an
     item updates both the draft and its library picker selection.
   - Create one ordinary native Jellyfin collection from the chosen title and
     selected media, then clear the title and selections for the next manual
     collection.

3. Individual Tag Collections
   - Show every saved library as an initially collapsed selector section.
   - Load metadata types only when a library is expanded, and metadata values
     only when a type is expanded.
   - Support all catalog metadata types, including Genres, Providers,
     Networks, Studios, Production Companies, Production Countries, Cast,
     Crew, Languages, Ratings and Classifications, Keywords, Existing
     Collection Metadata, direct Jellyfin fields, local NFO fields, and every
     other discovered type.
   - Sort values alphabetically; search values; page values fifty at a time;
     show matching counts; and show a person image when Jellyfin has one.
   - Create one live collection draft for every selected metadata value and
     remove that draft immediately when the value is unselected.
   - Let each draft have an editable collection title, an included/not-included
     creation choice, a current matching-media explanation, and a collapsible
     preview grouped by library.
   - Let each draft include matching media from additional saved libraries.
     The library where the value was selected is always included; Select All
     and Select None apply only to the other saved libraries.
   - Create checked, complete drafts as native Jellyfin collections, show
     progress and outcomes, and require a visible administrator choice before
     a same-title collection is used unchanged or skipped.

4. Combined Tag Collections
   - Reuse the full lazy, searchable, paginated metadata picker used by
     Individual Tag Collections.
   - Maintain one draft containing two or more selected metadata tags.
   - Display each selected tag's source library, metadata type, value, source
     matching count, and a per-tag removal control.
   - Match the union of the selected tags: an item matching any selected tag is
     included once, even when it matches more than one selected value.
   - Maintain one shared additional-library scope. Libraries where tags were
     selected are always included; Select All and Select None apply only to
     other saved libraries.
   - Provide an editable title, a collapsed preview grouped by library, a
     clear-draft control, visible same-title conflict choices, creation status,
     unique matching-media count, and a completion outcome.
   - Clear a successfully created draft so the administrator can start the
     next combined collection.

5. Multi-Match Tag Collections
   - Reuse the same full lazy, searchable, paginated metadata picker and
     shared-library scope as Combined Tag Collections.
   - Maintain one draft containing two or more selected metadata tags.
   - Match the intersection of the selected tags: an item is included only when
     it matches every selected metadata value in the shared selected-library
     scope.
   - Display each selected tag's source library, type, value, source matching
     count, and a per-tag removal control.
   - Provide an editable title, a collapsed preview grouped by library, a
     clear-draft control, visible same-title conflict choices, creation status,
     matching-media count, and a completion outcome.
   - Clearly state when no media matches every selected tag and prevent
     collection creation in that state.
   - Clear a successfully created draft so the administrator can start the
     next multi-match collection.

6. Collection Overview & Editor
   - Place this tab in the same dedicated secondary-tab row used by Media
     Tagging Manager, below the primary row, so its longer name does not force
     the primary tab row to extend or wrap off-screen.
   - Let an administrator choose to show collections made by this plugin,
     collections not made by this plugin, or both.
   - Scan and persist one flat overview of all current native Jellyfin
     collections, with a
  completion result and last-scan date and time. A later scan replaces the
  saved overview; reopening the dashboard uses the saved overview until an
  administrator scans again. The scan is not divided by library.
   - Provide an initially collapsed overview using the same expandable section
     pattern as Media Tagging Manager's Recommendations and Similar Titles
     overview, without library sub-sections. Show newly added collection names and media
     titles in the selected added color, and newly removed names and titles in
     the selected removed color.
   - Let the administrator edit a current collection's title and browse its
     media items in a scrollable, lazy-loaded, paginated picker. Provide Select
  All, Select None, Remove from Collection, and Add to Collection actions.
  Use Jellyfin posters when available. Add to Collection opens a poster-capable,
  thirty-collection-per-page picker. Save applies title and membership changes
  together; Close discards unsaved changes.
   - Provide Collection Manager cleanup choices to undo the last recorded
     collection action, remove collections recorded as made by this plugin, and
     remove media additions recorded as made by this plugin to existing
     collections not made by this plugin.

7. Default Art Settings
   - Provide an intentionally blank dashboard tab until its art-settings plan
     is defined.

8. Text Focused Art Settings
   - Provide an intentionally blank dashboard tab until its art-settings plan
     is defined.

9. Poster Focused Art Settings
   - Provide an intentionally blank dashboard tab until its art-settings plan
     is defined.

10. Logo Focused Art Settings
    - Provide an intentionally blank dashboard tab until its art-settings plan

11. Multi-Collection Gradient Art

Native Jellyfin and safety requirements
---------------------------------------
- Collections created by this plugin are normal Jellyfin collections. Native
  Jellyfin collection actions, including artwork and image controls, remain
  available in Jellyfin.
- The catalog and previews use only the most recent completed metadata scan,
  which is saved in Collection Manager's local Jellyfin plugin data so it can
  be reopened without rescanning.
- Matching remains server-side. Metadata-value pages contain fifty values; the
  flat collection overview keeps entries collapsed until individually opened.
- Tag-based collection drafts never silently duplicate or change a same-title
  collection. Their visible choices are to use the existing collection
  unchanged or skip the draft; an administrator can also change the draft
  title.
- The plugin must not expose media paths, credentials, API keys, NFO contents,
  local logs, or other private runtime data in public project files.

Compatibility and packaging requirements
----------------------------------------
- Build against Jellyfin.Controller and Jellyfin.Model 10.11.11 using net9.0.
- Target the Jellyfin 10.11 ABI declared by the package metadata.
- Preserve the Collection Manager Noncommercial License 1.0.
- A repository manifest is created only for a real release ZIP. Its version,
  target ABI, framework, release source URL, MD5 checksum, timestamp,
  description, branding image, and changelog must describe that exact artifact.
